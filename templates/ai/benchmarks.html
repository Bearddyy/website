## TLDR

For strix halo, the current best to use is Qwen 3.8 flash next, run with either gufo (open source) or halogen. If you want full context usage (256k) without losing much quality in the quant, go with Q4. Qwen 3.8 27B may be the best on memory constrained systems, but that is not the constraint on a strix halo machine and it being a mixture of experts, specifically with less active parameters means youll enjoy much faster token generation.

## WHAT TO OPTIMISE FOR

My main use for this box is agentic work, and that changes which numbers matter. An agent is not one long chat, it is hundreds of short rounds: read the conversation, call a tool, read the result, call another tool. The prompt grows every round and gets reread every round, so prompt processing dominates the day. A model that prefills at 1400 tokens per second finishes a 30k token context in well under a minute while the dense 27B needs over two, and you pay that tax on every single step.

So the ranking I settled on for agents: prompt processing first, generation speed second, time to first token a distant third, load time only if you swap models as often as I do. The MoE flash next model wins the first two outright, and with MTP speculative decoding on gufo the generation numbers climb further for free. Halogen is the one to chase if you want the same weights loading in under a second between tasks.

The dense 27B still has a job. It is the better pure reasoner per parameter and it fits in half the memory, so on a smaller box it is the right call. On 128GB of unified memory there is no reason to compromise, run the biggest MoE that fits at 4 bit and let the bandwidth do the rest.
